# Player adapters

`local.ts` owns the video element binding, object URL, listeners, cancellation, observations, and disposal.
`PlayerAdapter` declares mandatory controls and optional rate/buffering capabilities. Files never enter a room serializer or serializable store.
The worker hashes at most three 1-MiB samples using the exact room-specific v1 encoding and incremental SHA-256.
A disposed adapter cannot publish readiness or resume a newer player. Browser reload requires file reselection.
`drawThumbnail` is an optional, browser-local adapter operation. Local previews use a lazy second decoder without seeking the playback element. Bilibili progressively caches all compressed sheets in background workers grouped by opaque source-origin IDs from the helper. Source groups and foreground control replies have independent capacity; video pumping and seeking do not pause other CDN downloads. Transient metadata/image failures recover with capped backoff while completed images stay cached and other source groups continue. The hover path reads only memory and decodes the requested cell at the displayed preview size. Cache updates refresh stationary hovers, and cached sheets survive moving between targets without repeat downloads. Coalesce pointer movement into serial draws for the latest target. Each adapter releases background work, its decoder, and cached images on disposal; cancellation prevents stale frames from appearing after preview dismissal or media changes. Preview failures retain the target time without affecting synchronization or readiness.
B0 has validated a separate Tampermonkey-assisted MediaSource prototype with danmaku and independent platform sessions on desktop Chromium and Firefox. See DESIGN §8 for the accepted interfaces and bounds.

`../bilibili/adapter.ts` implements the production Bilibili adapter with the same native observations and room synchronization controls. It owns bounded SIDX/MediaSource delivery, per-player helper channels, request cancellation, source buffers, and danmaku disposal.
The backend `modules/sync/internal/helper` package keeps provider responses and signed locations in helper memory. The room receives only stable matching metadata. Local volume, mute, and danmaku settings stay outside shared state.

The helper exposes actual AVC track quality IDs. Initial loading selects the highest playable tier unless a browser-local quality preference is available. An unavailable preferred tier falls back to the highest playable tier without erasing that preference. Selecting a quality disposes the previous adapter, opens a new player channel, and reports readiness before converging to room playback.
SIDX direct references use their full 31-bit size. The adapter reads and appends chunks of at most 256 KiB without assembling whole fragments, including references above 64 MiB.
Audio/video work alternates within bounded passes. Each track owns one cursor, one current chunk, and at most one read-ahead chunk. Network reads overlap native appends. The helper fills bounded network windows of at most 2 MiB independently of the 256 KiB page chunks. SIDX byte rates estimate 64 MiB video / 8 MiB audio budgets with up to four seconds of history and 1–30 seconds ahead. Startup uses a smaller target; sustained buffering adapts to observed read delays under the byte budget.
Browser quota pressure triggers eviction and one retry, then holds the same chunk while playback can free space. No playable headroom means a bounded playback failure.
Seeks immediately cancel obsolete helper media reads and expiry refreshes, reset incomplete parsers, clear read-ahead windows, and discard late replies. Same-segment danmaku requests remain active. Browser memory and codec limits still apply; the byte budgets estimate compressed buffering rather than actual allocations.
Played-data eviction cuts within the preceding fragment to preserve the current keyframe and its dependent frames. A rounded SIDX timestamp can fall after the actual keyframe; cutting exactly there can remove the seek target and leave a completed fragment permanently missing from the native buffer.
Native seeks wait for target data without the initial file-load deadline. A newer seek, disposal, or media error ends the wait; superseded synchronization failures cannot replace the current room state with an error.
Root `versions.toml` supplies the helper release version; `modules/helper/dist/release.json` is generated metadata for script delivery, handshake validation, and onboarding. The protocol version remains separate.
Live quality-switching evidence is required beyond the historical B0 fixed-quality baseline.
